# Creating Project Skills

When adding a project-specific skill:

1. Give it a clear, task-focused name and state when it should be used.
2. Record the repository's established patterns and constraints, not assumptions about files that do not exist yet.
3. Keep instructions actionable, concise, and consistent with `.clinerules` and `context/master-plan.md`.
4. Include relevant validation steps and tests.
5. Avoid duplicating general project rules unless a skill needs them for task-specific clarity.
